<div class="sec-head"><span class="sec-num">1</span><h2 class="sec-title">A vector is an arrow, not a list</h2></div>

Write a vector as `[3, 2]` and it looks like bookkeeping. Draw it, and it's an arrow from the origin that walks 3 steps right and 2 steps up. Same object, two readings — and the geometric one is the reading that makes everything downstream click.

Two properties fall directly out of the picture: how **long** the arrow is (its magnitude) and which way it **points** (its direction). Length comes from the Pythagorean theorem generalized to *n* dimensions:

<Formula name="magnitude (L2 norm)">
‖v‖ = √(v₁² + v₂² + ⋯ + vₙ²)
</Formula>

For `v = [3, 2]`: ‖v‖ = √(9 + 4) = √13 ≈ 3.61.

<div class="sec-head"><span class="sec-num">2</span><h2 class="sec-title">Adding vectors is walking, then walking again</h2></div>

To add two vectors, walk the first one, then walk the second one starting from where you landed. Algebraically that's just adding components; geometrically it's "tip-to-tail," and it traces out a parallelogram.

<Formula name="vector addition">
a + b = [a₁+b₁, a₂+b₂, …, aₙ+bₙ]
</Formula>

Scalar multiplication (`2·v`) is the same arrow, just stretched or shrunk — negative scalars flip it around. This is the entire vocabulary a neural network uses to move points around before anything nonlinear happens: **stretch, rotate, add**.

```python
def add(a: list[float], b: list[float]) -> list[float]:
    return [ai + bi for ai, bi in zip(a, b)]

def scale(v: list[float], k: float) -> list[float]:
    return [k * vi for vi in v]
```

<div class="sec-head"><span class="sec-num">3</span><h2 class="sec-title">The dot product measures agreement</h2></div>

The dot product has an algebraic definition and a geometric one, and the whole trick of linear algebra intuition is holding both in your head at once.

<Formula name="algebraic">
a · b = a₁b₁ + a₂b₂ + ⋯ + aₙbₙ
</Formula>

<Formula name="geometric">
a · b = ‖a‖ ‖b‖ cos(θ)
</Formula>

Set them equal and something useful pops out: the dot product is large and positive when two vectors point the *same way*, zero when they're perpendicular, and negative when they point opposite ways. It's a number that measures **directional agreement**, scaled by how long the vectors are.

Divide out the lengths and you get **cosine similarity** — agreement with the lengths ignored, just "how aligned are these two directions":

<Formula name="cosine similarity">
cos(θ) = (a · b) / (‖a‖ ‖b‖)
</Formula>

Every transformer attention score is a dot product. A query vector `q` and a key vector `k` are compared with `q · k` — high agreement means "this key is relevant to this query." Scale by `√d` to keep the numbers well-behaved, run everything through softmax, and you have attention weights:

<Formula name="scaled dot-product attention">
Attention(Q, K, V) = softmax(QKᵀ / √d) · V
</Formula>

Matrix multiplication, then, is just "apply this transformation to every vector at once" — and multiplying two matrices together (`M₂M₁`) means "do transformation 1, then transformation 2." That's why deep networks stack matrix multiplies: each layer is another reshaping of space, with a nonlinearity (ReLU, GELU, …) bent in between so the whole stack can't collapse back into one giant matrix.

```python
def matmul(A: list[list[float]], B: list[list[float]]) -> list[list[float]]:
    rows_A, cols_A = len(A), len(A[0])
    rows_B, cols_B = len(B), len(B[0])
    assert cols_A == rows_B, "inner dimensions must match"

    result = [[0.0] * cols_B for _ in range(rows_A)]
    for i in range(rows_A):
        for j in range(cols_B):
            result[i][j] = sum(A[i][k] * B[k][j] for k in range(cols_A))
    return result
```

<div class="sec-head"><span class="sec-num">5</span><h2 class="sec-title">Independence, span, and basis</h2></div>

A set of vectors is **linearly independent** if none of them can be built by combining the others — each one adds a genuinely new direction. If one vector is just a scaled copy of another, they're **dependent**, and together they can only ever reach points along a single line, no matter how you combine them.

The set of every point reachable by combining a group of vectors is their **span**. A minimal set of independent vectors whose span covers the whole space is a **basis** for that space — in 2D, any two independent vectors will do; î and ĵ are just the tidiest choice.

The quickest 2D independence test: two vectors `[a,b]` and `[c,d]` are independent exactly when `ad − bc ≠ 0` — that's the determinant, and it's also the (signed) area of the parallelogram they sweep out. Zero area means the vectors collapsed onto the same line.

<div class="sec-head"><span class="sec-num">6</span><h2 class="sec-title">Rank: how many genuinely new directions survive</h2></div>

**Row reduction** (Gaussian elimination) is the systematic version of "notice when a row is secretly a combination of other rows." You repeatedly subtract multiples of one row from another until the matrix is in a staircase shape — each step either reveals a new independent direction (a pivot) or reveals that a row was redundant all along (it zeroes out completely).

The number of pivots you're left with is the **rank** of the matrix — literally a count of how many independent directions it actually contains, out of however many rows or columns it was written with. A "full rank" matrix wastes nothing; a "low rank" matrix is quietly doing much less work than its size suggests.

<div class="tablewrap">
| Concept | Question it answers |
|---|---|
| Independence | Does this vector add anything new? |
| Span | What can be reached by combining these vectors? |
| Basis | What's the smallest set that reaches everything? |
| Rank | How many independent directions does this matrix actually have? |
</div>

<div class="sec-head"><span class="sec-num">7</span><h2 class="sec-title">Why LoRA is a rank argument</h2></div>

Fine-tuning a large model means learning an update `ΔW` to add to its weight matrix `W`. If `W` is, say, 4096 × 4096, that's 16.7 million numbers to learn — for every layer, for every fine-tune. LoRA's bet is that the *useful* update barely uses all those directions: it constrains `ΔW` to be low rank by writing it as a product of two thin matrices.

<Formula name="low-rank adaptation">
ΔW = A · B   (A is d×r, B is r×d, r ≪ d)
</Formula>

This is the same rank idea from Section 6, applied on purpose: by forcing the update through a narrow r-dimensional bottleneck, you're betting that a fine-tune only needs a handful of new "directions of change," not a full-rank rewrite of the whole matrix. When `r` is small (8, 16, 64) compared to `d` (thousands), the parameter savings are enormous — and in practice, it works remarkably well.

<Callout label="Tying it together">
**Embeddings** put meaning into vector space so distance and angle mean something. **Attention** uses the dot product to score relevance between vectors. **LoRA** uses rank to make learning cheap. Three different corners of a transformer, one shared vocabulary.
</Callout>

<WorkTask label="Task 1 · Implement" title="Dot product, norm, and cosine similarity — from scratch">

No `numpy`. Fill in the three functions below using only what Sections 1 and 3 covered.

```python
import math

def dot(a: list[float], b: list[float]) -> float:
    # TODO: sum of elementwise products
    ...

def norm(v: list[float]) -> float:
    # TODO: sqrt of the sum of squares
    ...

def cosine_similarity(a: list[float], b: list[float]) -> float:
    # TODO: dot(a, b) / (norm(a) * norm(b))
    ...
```

<Solution>

```python
import math

def dot(a: list[float], b: list[float]) -> float:
    return sum(ai * bi for ai, bi in zip(a, b))

def norm(v: list[float]) -> float:
    return math.sqrt(dot(v, v))

def cosine_similarity(a: list[float], b: list[float]) -> float:
    return dot(a, b) / (norm(a) * norm(b))
```

</Solution>

<WorkTask label="Task 2 · Apply" title="Which pair of &quot;words&quot; is more alike?">

Three toy 5-dimensional embeddings (made up, but shaped like real ones):

```python
cat      = [0.9, 0.1, 0.4, 0.7, 0.2]
kitten   = [0.8, 0.2, 0.5, 0.6, 0.3]
airplane = [0.1, 0.9, 0.2, 0.0, 0.8]
```

Using your `cosine_similarity` from Task 1, compute similarity(cat, kitten) and similarity(cat, airplane). Which pair is closer in direction? Does it match your intuition about the words?

<Solution>

```python
print(cosine_similarity(cat, kitten))    # ≈ 0.985
print(cosine_similarity(cat, airplane))  # ≈ 0.516
```

cat and kitten point in nearly the same direction in this toy space (cosine ≈ 0.985) — much closer than cat and airplane (≈ 0.516). This is exactly how a real embedding model powers semantic search: rank every candidate by cosine similarity to the query and return the closest directions.

</Solution>

<WorkTask label="Task 3 · Reason" title="Spot the dependent vector, by eye">

Three vectors: `u = [1, 2, 3]`, `v = [2, 4, 6]`, `w = [1, 0, 0]`. Without doing full row reduction — using Section 5's independence test and Section 6's definition of rank — answer: (a) which two vectors are linearly dependent, and (b) what is the rank of the 3×3 matrix formed by stacking `u`, `v`, and `w` as rows?

<Solution>

**(a)** `v = 2u` exactly — `v` is just `u` stretched by 2, so `u` and `v` are dependent; they point along the same line and contribute only one direction between them.

**(b)** Row reduction would eliminate `v` entirely (row2 − 2·row1 = zero row), leaving two independent rows: `u` and `w` point in genuinely different directions (neither is a multiple of the other). So the matrix has **rank 2**, not 3 — three rows were written down, but only two independent directions actually exist, exactly the gap LoRA exploits on purpose.

</Solution>
