<section class="lesson">
<div class="sec-head"><span class="sec-num">1</span><h2 class="sec-title">A matrix is where the basis vectors land</h2></div>

A 2×2 matrix is completely determined by two vectors: where it sends `e₁ = [1, 0]` and where it sends `e₂ = [0, 1]`. Those two images *are* the columns of the matrix — there's no other information hiding in it.

That falls out of linearity, the one rule every matrix transformation has to obey: `M(a·u + b·v) = a·M(u) + b·M(v)`. Every point in the plane is `x·e₁ + y·e₂` for some `x, y`, so once you know where the two basis vectors land, linearity hands you every other point for free: `M([x, y]) = x·(column 1) + y·(column 2)`.

That's the lens for this whole lesson. Instead of reading a matrix as a grid of numbers, read it as: 'where does this send `e₁`, and where does it send `e₂`' — and the rest of the plane's fate is already decided.

</section>

<section class="lesson">
<div class="sec-head"><span class="sec-num">2</span><h2 class="sec-title">Rotation: spinning without stretching</h2></div>

A rotation by angle `θ` (counterclockwise) sends `e₁` to `[cos θ, sin θ]` and `e₂` to `[-sin θ, cos θ]` — walk those two points around the unit circle and you'll see both basis vectors swept counterclockwise by exactly `θ`, still 90° apart.

<Formula name="2D rotation matrix">
R(θ) = [[cos θ, −sin θ], [sin θ, cos θ]]
</Formula>

Multiply any vector by `R(θ)` and it keeps its length and its angle to every other vector — nothing stretches, nothing shears. That's a property of the matrix itself: its columns are unit length and perpendicular to each other (an **orthogonal** matrix, `Rᵗ R = I`), and `det(R) = cos²θ + sin²θ = 1`, confirming area is preserved and orientation isn't flipped.

```python
import math

def rotation_matrix(theta: float) -> list[list[float]]:
    c, s = math.cos(theta), math.sin(theta)
    return [[c, -s], [s, c]]

def apply(M: list[list[float]], v: list[float]) -> list[float]:
    return [sum(M[i][j] * v[j] for j in range(len(v))) for i in range(len(M))]
```

</section>

<section class="lesson">
<div class="sec-head"><span class="sec-num">3</span><h2 class="sec-title">Scaling, shearing, reflection — the other elementary moves</h2></div>

Three more basic transformations, each a one-line edit to the identity matrix:

- **Scaling** stretches each axis independently: `diag(sx, sy)` sends `e₁ → [sx, 0]` and `e₂ → [0, sy]`.
- **Shearing** tilts one axis while leaving the other fixed: `[[1, k], [0, 1]]` leaves `e₁` in place and slides `e₂` sideways by `k`.
- **Reflection** flips across a line: reflecting across the x-axis is `[[1, 0], [0, -1]]` — it negates just the y-coordinate.

```python
def scale_matrix(sx: float, sy: float) -> list[list[float]]:
    return [[sx, 0.0], [0.0, sy]]

def shear_matrix(k: float) -> list[list[float]]:
    return [[1.0, k], [0.0, 1.0]]

def reflect_x_matrix() -> list[list[float]]:
    return [[1.0, 0.0], [0.0, -1.0]]
```

As Lesson 02's determinant covered, `det` tells you what each of these does to area and orientation: scaling by `(sx, sy)` has `det = sx·sy` (area multiplies by that factor); shearing has `det = 1` (area is preserved, only angles change); reflection has `det = -1` (area is preserved but orientation flips — a shape and its mirror image can never be rotated into each other, only reflected).

</section>

<section class="lesson">
<div class="sec-head"><span class="sec-num">4</span><h2 class="sec-title">Composing transformations is matrix multiplication — and order matters</h2></div>

To apply transformation `A`, then transformation `B`, to a vector `x`: first `Ax`, then `B(Ax) = (BA)x`. So "`A` then `B`", as a single matrix, is `BA` — read right to left, innermost transformation first. Because matrix multiplication generally isn't commutative, `AB ≠ BA`, composing transformations in a different order genuinely produces a different transformation.

Take `R` = rotate 90° (`[[0, -1], [1, 0]]`) and `S` = scale x by 2 (`[[2, 0], [0, 1]]`), applied to `v = [1, 1]`:

- **Rotate then scale** (`S·R`, rotate happens first): `Rv = [-1, 1]`, then `S(Rv) = [-2, 1]`.
- **Scale then rotate** (`R·S`, scale happens first): `Sv = [2, 1]`, then `R(Sv) = [-1, 2]`.

Same two operations, same starting vector, two different endpoints — `[-2, 1]` versus `[-1, 2]`. Order isn't a bookkeeping detail here; it's the difference between two distinct transformations that happen to share the same two ingredients.

<Callout label="Where this bites">
This is exactly why the order of layers in a network, or the order you apply `Q @ Kᵀ` versus `K @ Qᵀ` in attention, isn't arbitrary notation — swapping the order of two matrix operations is a different computation, not a cosmetic rewrite.
</Callout>

</section>

<section class="lesson">
<div class="sec-head"><span class="sec-num">5</span><h2 class="sec-title">Eigenvectors: the directions a matrix only stretches</h2></div>

For most vectors, a matrix sends them off in a genuinely new direction — rotated, sheared, tangled up with the matrix's other effects. But every square matrix has special directions it leaves alone, up to a scale: nonzero vectors `v` such that `Av = λv` for some scalar `λ`. Along an **eigenvector** `v`, the matrix acts like plain multiplication by its **eigenvalue** `λ` — no rotation, just stretching (or shrinking, or flipping if `λ < 0`).

<Formula name="Eigenvalue equation">
Av = λv, for some nonzero vector v and scalar λ
</Formula>

To find them, rewrite as `(A - λI)v = 0`. A nonzero `v` solving this exists only if `A - λI` is singular — `det(A - λI) = 0`, the **characteristic equation**. For a 2×2 matrix with trace `tr(A) = a + d` and determinant `det(A) = ad - bc`, that equation is always a quadratic in `λ`:

```python
def eigenvalues_2x2(M: list[list[float]]) -> tuple[float, float]:
    (a, b), (c, d) = M
    trace, det = a + d, a * d - b * c
    disc = trace ** 2 - 4 * det          # assumes real eigenvalues (disc >= 0)
    sqrt_disc = disc ** 0.5
    return ((trace + sqrt_disc) / 2, (trace - sqrt_disc) / 2)

def eigenvector_2x2(M: list[list[float]], eigenvalue: float) -> list[float]:
    (a, b), (c, d) = M
    if b != 0:
        return [b, eigenvalue - a]      # solves (a-λ)x + by = 0
    return [eigenvalue - d, c]           # fallback when b == 0
```

</section>

<section class="lesson">
<div class="sec-head"><span class="sec-num">6</span><h2 class="sec-title">Where this exact computation shows up: PCA, RNN stability, spectral clustering</h2></div>

Three places you'll meet eigenvalues again, dressed in different clothes:

- **PCA.** Build the covariance matrix of your data, and its eigenvectors are the principal directions — the eigenvector with the largest eigenvalue points along the direction your data varies the most, with the eigenvalue itself equal to how much variance lies along it.
- **RNN stability.** Applying the same weight matrix once per time step is repeated matrix multiplication, `Aᵗ`. Decompose the input along the matrix's eigenvectors and each component scales by `λᵗ` on its own. If the largest `|λ|` (the **spectral radius**) exceeds 1, that component grows without bound over enough steps — an exploding gradient; if it's below 1, that component decays to nothing — a vanishing gradient. "Keep the spectral radius near 1" is literal design advice for recurrent architectures, not a metaphor.
- **Spectral clustering.** Build a graph Laplacian from pairwise similarities between points, and its eigenvectors with the smallest eigenvalues give a continuous relaxation of cluster membership — points in the same cluster land close together in that eigenvector's coordinate.

<Callout label="The pattern underneath">
All three questions reduce to the same one: apply this matrix over and over (or just once, to summarize a whole dataset's spread) — which directions dominate, which vanish, and which stay perfectly still? That question's answer is always an eigendecomposition, however different the surface problem looks.
</Callout>

</section>

M = [[2, 1], [1, 2]]

Both checks confirm `Mv = λv` exactly: `[1, 1]` only gets stretched by 3, `[1, -1]` is left completely unchanged by 1 — neither one rotates even slightly, which is the whole definition of an eigenvector.
